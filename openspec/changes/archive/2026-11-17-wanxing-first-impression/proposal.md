# 第一印象（wanxing-first-impression）

## Why

萬星门面今天的第一个印象是**一份说明书 + 一扇上锁的门**：首屏是价值文案、三块自述功能卡和计费口径表，
零个可点的 agent；而站点里唯一的活体读数（19 个 agent 在役 · 近 7 天 46 回合）被压在页脚 12px 灰字里。
这个层级是倒置的——萬星真正的产品身份是**一台正在跑的机器**（在役/驻留/结算/机群观测），不是一份介绍。

三处被真机证实的结构性缺陷：

1. **目录卡片承载同一句话。** 生产 API 实测 19/19 个 agent 的 `examples` 为空、`skills` 为空，
   于是 19 张卡渲染同一句填充语（「对话即试用——直接问它一个你手上的真实问题」），折叠区标题
   全部退化成「slug」。卡片之间没有任何区分信息，但每张挂了 2–6 枚同声量彩色徽章。
2. **「可对话」是一次假承诺。** 19/19 卡片带 `chatable`、都渲染「对话」CTA；未登录访客点进去只有
   一堵「使用寻数账号登录」的墙，登录完成也不落回刚刚那个问题。匿名梯队（`visitor-token` 铸临时凭据）
   只对嵌入源开放，对话车道按域规则要求登录。
3. **Agent 的回答不可读。** `ChatView` 与 `EmbedView` 都用 `whitespace-pre-wrap` 原样输出，全仓无任何
   markdown 渲染（无依赖、无自研）。真机截图可见回答把 `**壹座（底座/创作面）**`、`- **谦面**` 原样漏出。
   这条同时污染四条产品线经 `copilot.js` 嵌入的副驾——它的伤害超过任何布局改动。

## What Changes

**① 首屏改成活体读数，再给真卡片**

- `#/` 首屏第一眼是在役 agent 数、近 7 天回合数（复用页脚已在读的 `/api/wanxing/v1/status`），
  随后是 3–6 张真实 agent 卡（同一份目录数据），再往下才是定位与调用示例。
- 删除三块自述功能卡（服务目录 / A2A 调用 / 计量与计费）与首屏计费口径表；计费口径留在 `#/docs`。
- 读数不可达时降级为不影响布局的静态行，首屏不出现「读取中」抖动。
- **BREAKING（对现有规格）**：现行 `wanxing-web` 规格要求 intro「完全静态、不依赖任何 live API」。
  本刀把它改成「唯一的活体依赖是公开 status 聚合端点，且该依赖失败时不影响任何布局」。
  目录接口不可达时首屏仍渲染（无卡片 + 一句说明），不得整屏空白。

**② 每张卡只说一件事，且不说谎**

- 卡片信息元收敛为四件：一句「它能替你干什么」（`description` 截断到一行的语义版本）、一枚主事实徽标
  （沿用 `status-facts.js` 的单一事实表，其余徽章降级为不抢主徽标的次级信号）、分类信号（一个，不是彩虹）、
  一个真实入口。
- 删除「每张卡都渲染同一句填充语」的兜底：`examples` 为空时不再输出那句提示，改为不渲染该区域。
  折叠区在没有 `skills` 时不再以「slug」为标题展开——slug 作为对接标识留在详情页与复制按钮里。
- 入口按事实选择：可对话且未暂停 → 「对话」；其它 → 「看详情」。
- 卡片补上「近 7 天回合」只在有值（>0）时渲染（现状已如此，保留），零回合不占位。

**③ 登录不再是死路：问题带过去，登录后落回来**

- 目录卡片与详情的对话入口把用户当前的示例问题编码进 URL（`#/chat/<slug>?q=…`，该契约已存在）。
- 未登录进入 `#/chat/<slug>` 时，登录按钮把完整 hash（含 `?q=`）作为 `returnTo`，登录回调后
  回到同一对话并把问题预填在输入框（不自动发送）。
- 保持**登录制**不变：不把匿名梯队接到对话车道，不改「匿名访客」的域边界与结算语义。
- 登录墙从占满一屏的中央提示，改为**在对话页原地**的登录条：agent 名称、说明、示例问题与登录按钮同屏，
  访客在点击登录前就能看清自己在跟谁说话。

**④ Agent 的回答按 markdown 渲染（两个外壳共用一处）**

- 在 `chat-core.js` 增一个受控 markdown 渲染器（只有对话核心知道这件事，`ChatView` 与 `EmbedView` 都走它）：
  段落、有序/无序列表、行内 `code`、代码块、粗体、标题（收敛到对话气泡可用的小尺度）、链接、
  水平线；**其余一律按纯文本转义输出**（不允许原始 HTML 注入）。
- 渲染范围是 assistant 消息；user 消息保持纯文本（用户输入原样呈现，不做解释）。
- 气泡内排版：代码块等宽 + 横向滚动、列表有缩进、链接新窗口 + `rel="noopener noreferrer"`。

**⑤ 详情页说清「它是谁 · 现在怎样 · 怎么接」**

- 三段：它是什么（名称/版本/一句定位/标签）· 现在什么状态（主事实徽标 + 最近调用量）·
  三种接法（对话 / A2A curl 样例可复制 / 嵌入一行脚本），以及可见性与谁能调（公开/暂停/需登录）。
- 保留现有 A2A 路由与 slug 复制；示例问题存在时给「试问」入口，不存在时不编造。

**⑥ 控制台舰队卡先给结论（最小版）**

- 每张舰队卡首行给一句人能读的结论（如「33 回合在跑，无健康告警」「该跑没跑 · 按声明应有 4 次」
  「尚无调用」「状态未知」），来源是已有的事实表与 health，不新增取数。
- 七个管理按钮收成两级：主操作（配置 / 记录）+ 「更多」收纳（暂停 / 记忆 / 额度 / 嵌入 / 允许清单）。
  面板、端点、testid 全部不变。

**⑦ 钉住萬星自己的视觉与产品世界**

- 新增 `fd-wanxing/PRODUCT.md` 与 `fd-wanxing/DESIGN.md`：把现存世界（slate 中性面 + 印章红
  `#a6402f` 单强调色 + 中文优先 + 单站点记号）写成结论，供本刀与后续各刀共用。
  工作区根的两份文件描述的是官网（夜色控制台 + 薄荷信号），不是萬星——万星此前没有自己的视觉权威文档。

## Non-goals

- **不把匿名梯队接到对话车道。** 那要改 `CONTEXT.md` 的「匿名访客」边界与结算语义，另立专项。
- **不改任何后端契约。** `status` / `agents` / `chat` 端点的字段与取值不变；本刀只改消费侧怎么读与怎么排。
- **不做目录策展闸。** 生产目录里混着 `probe` / `security-pending` 内部 agent——把它们挡在公开目录外
  是运营策展规则，需要单独定义「哪些 agent 对外」，不在本刀发明。
- **不重做控制台信息架构。** 五个 tab 的归属、任务面、机位面、统计面不动；只做舰队卡的首行结论与按钮分层。
- **不改嵌入车道的身份阶梯与宿主协议。** `copilot.js` 的握手、`identify/context/intents` 钩子、
  匿名升级路径不动；嵌入面只共享 markdown 渲染这一处。
- **不引入 markdown 依赖。** 渲染器自持（受控子集），不新增 npm 包。
- **不改动万星视觉世界本身。** 本刀是 refinement：保留印章红、slate 双色与现有排版，不做品牌重设计。

## Capabilities

### New Capabilities

（无——本刀不引入新能力，全部落在既有 `wanxing-web` 上。）

### Modified Capabilities

- `wanxing-web`:
  - 「The public intro view is the default landing」：从「完全静态」改为「首屏活体读数 + 真卡片，
    活体依赖失败不影响布局」；功能卡与计费口径表移出首屏。
  - 「The public catalog page lists agents for humans」：卡片信息元件收敛为四件、单一主徽标、
    删除同质填充语与空折叠区、入口按事实选择。
  - 「The chat view lets logged-in visitors converse with a chatable agent」：登录墙原地化 +
    登录后落回原对话与预填问题；assistant 消息按受控 markdown 渲染；user 消息保持纯文本。
  - 「The catalog links chatable agents to the chat view」：入口在不可对话/已暂停时改为详情，
    可对话时携带当前示例问题。
  - 新增：agent 详情页三段结构（是什么 / 现在怎样 / 怎么接）与可见性说明。
  - 「The fleet tab renders deployment cards」：首行结论 + 管理动作两级分层（面板与 testid 不变）。

## Impact

- 代码：`wanxing-web/src/views/{IntroView,CatalogView,AgentDetailView,ChatView}.jsx`、
  `wanxing-web/src/views/EmbedView.jsx`（仅渲染共用）、`wanxing-web/src/chat-core.js`（markdown 渲染器）、
  `wanxing-web/src/index.css`（气泡内 markdown 排版与浏览器 surface 适配）、
  `wanxing-web/src/views/console/FleetView.jsx`（首行结论 + 按钮分层）。
- 测试：`wanxing-web/test/`（新增 markdown 渲染器用例、卡片入口选择用例、intro 活体读数降级用例；
  现有 `chat-core` / `views` 用例按新结构更新，不得删除既有断言所保护的契约）。
- 文档：新增 `fd-wanxing/PRODUCT.md`、`fd-wanxing/DESIGN.md`。
- 发布：无新镜像仓、无新依赖、无后端改动——常规静态出片。
- 风险：intro 与目录共用 `status` / `agents` 端点，首屏多一次取数（同一端点，已缓存页脚那次调用）；
  登录回流依赖已存在的 `returnTo` 机制，但「带 `?q=` 的完整 hash 往返」需真机验证。
