# Design — 跨线副驾铺开

## D1 为什么「铺开」不是写代码

能力四件套（绑定治理、解析端点、loader、宿主协议）都是规格里已有的要求，且已在识律一条线上真机运行。
剩下三条线之所以是 unbound，原因是**没有人做绑定这个动作**，以及**没有 agent 可以被绑**。

所以本刀的性质是：**治理 + 接入核对**，而不是工程。设计篇幅因此不在代码上，而在
「每条线的决定是什么、由谁在什么时候验」。

## D2 顺序：official → wire → facet → lex 回收 → （门槛）壹座

```
official  静态 Astro，零登录，陌生人      <- 匿名车道最硬的试金石，先做
wire      已上线对外面 + 控制台，有登录态
facet     谦面产品面
lex       已在役，但用的是手写协议        <- 回收为 loader（保留身份钩子）
---- 门槛：以上三线真机四点全过 ----
yizuo     壹座，在役 + 有真实用户         <- 最后动，且落在 paas 仓
```

裁决理由：

- **official 先做**。它没有登录态、没有控制台、访客是纯粹的路过者——是匿名阶梯唯一能暴露真问题
  的场景。若别名渠道在公开站点能跑通，「匿名双门」这个设计才算被验证过。
- **lex 回收排在其后**。它是当前唯一在跑的实现，动它等于动在役生产；而它的手写封装里有一个
  必须保真的东西：宿主自己的 Logto 票经 `identify()` 递送（`fd-lex/web/src/console/WanxingCopilot.tsx`）。
  loader 的身份钩子正是为此设计的，但**只有先在三线把钩子跑熟，才敢迁这一个**。
- **壹座最后**。它是唯一一个「已在役 + 有真实用户 + 有另一套不兼容实现」的宿主。

## D3 壹座的门槛为什么写成硬条件

壹座 paas 侧有 `CopilotDock`（`paas/lib/copilot-presets.js`，同源 iframe + 形状解析的聚焦预设），
与萬星 widget 在身份、结算、上下文协议上都不兼容。两套并存意味着同名不同命。

如果把壹座并进本刀：本刀就同时在做「协议首验证」（三线）、「宿主回收」（lex）、「产品迁移」（壹座）
三件互不相同的事，任何一件出问题都分不清是哪件的锅。

所以写成硬门槛：**三线在生产真机跑通「匿名对话 + 问询卡 + 宿主意图」之后**才动壹座。这不是拖延，
是把未知摊开——三线跑完，剩下的就是「删一套、挂一套」的机械动作。

## D4 匿名策略按线定的判据

```
official   匿名开   （公开站点，访客是陌生人；开匿名是它的存在意义）
wire       对外面匿名开、控制台内匿名关
facet      按产品面定，默认关
lex        已关（控制台内，登录态齐备）
yizuo      迁移时再定
```

判据一句话：**页面上的读者有没有我们可信的身份**。有（控制台内登录用户）就不需要匿名；
没有（公开站点）就必须有，否则贴上去第一眼是「登录后开始对话」，登录还跳到别的产品。

## D5 成本护栏

official 开匿名会真的产生平台补贴支出。所以：

1. 先只在 official 开，观察 24h 的匿名日额消耗曲线（`/api/wanxing/v1/console/embeds` 侧的用量）。
2. 消耗在预期内，再决定 wire 对外面是否放开。
3. 每访客匿名日额是既有机制，本刀不改限额——只决定**在哪些源上暴露它**。

## D6 回收 lex 的保真清单

迁移时必须逐条核对（否则就是「协议对了、身份丢了」）：

| 维度 | 迁移前 | 迁移后必须仍成立 |
|---|---|---|
| 身份 | 手写 fetch 宿主 Logto 票再注入 | loader `identify()` 返回同一张票 |
| 首轮上下文 | 手写 context push | `context()` 钩子返回同形状 |
| 意图 | 手写 intent 监听 | `intents` 映射同动词 |
| accent | 硬编码 | 绑定里配 |
| 死卡 | 手写判断 | loader 自带（unbound/closed 不注入） |

任何一条不成立 = 迁移不算完成。

## 风险与验收

| 风险 | 缓解 |
|---|---|
| 匿名在公开站点被刷 | 既有 per-vid 日额封顶；observe 24h 再放开第二条线 |
| 某线没有合适 agent | 登记为该线阻塞项，不临时编人设 |
| 三线协议首验证撞出 loader 缺陷 | 修在 `wanxing-web` 的 loader 要求下（既有 capability），不在本刀另造 |
| 壹座被人顺手做了 | 门槛写进 tasks 的前置条件，apply 阶段不满足即停 |

验收（每条线四点，缺一不算接通）：
1. 生产域名打开页面，副驾浮起
2. 匿名（或该线层级）发一轮，收到回复
3. 触发一次问询卡并作答
4. 触发一次宿主意图，宿主执行并回结果
