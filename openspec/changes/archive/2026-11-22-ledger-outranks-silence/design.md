# Design

## Context

`status-facts.js` 是一张纯函数事实表，四个消费面都调它。它的优先级链是一个 `if` 序列，改它等于改
全站状态语义——所以这条改动虽只有两行代码，但需要留下「为什么这个顺序才是对的」的记录。

见 proposal.md - Why。这里有价值的是：为什么是「台账赢」而不是别的解法。

## Goals / Non-Goals

**Goals:**
- 一张卡上不会再出现「徽标 0 回合 / 数字 9 回合」这种自相矛盾。
- 改动只落在顺序上，不新增第八种事实、不改任何字段。

**Non-Goals:**
- 不去消除两个数据源本身的存在（它们各有用途：台账管账，观测管健康）。
- 不改门面 `statusFor()`——它已经是「近 7 天有无调用」的单一权威。

## Decisions

**D1 · 台账赢，因为它测的是**所问的那件事**。**
`serving` 的定义就是「近 7 天有人调」，而 `turns7d` 正是对着这件事数出来的；`silent` 是观测面
在某个窗口里没看到心跳/事件。当问题就是「有没有人调用」时，直接数调用记录的那个来源更可信。
*备选*：观测面赢（现状）—— 已被实撞否定：它把有 9 回合的 agent 说成无调用。

**D2 · 不让它变成「冲突就报错」的第三态。**
第三种状态听起来更诚实，但代价是：任何一次观测面延迟都会让卡片变成告警，读者要学会区分「真冲突」
和「采样还没到」。而这条链的设计目标恰恰是**一枚徽标**。

**D3 · 顺序换位，而不是给 `factOf` 加参数。**
加一个 `preferLedger` 开关会让四个调用面各自决定信谁——那正是这张表要消灭的东西。换位让所有面同时
得到同一个答案。

**D4 · `stalled` 保持原位。**
`silent + stalled` 说的是「声明了节奏却一次没跑」，与「有回合」在语义上互斥，不存在冲突。它排在
「在役」之前是对的。

## Risks / Trade-offs

- **观测面的静默信号被弱化** → 缓解：它仍然决定 `idle` 的徽标，也仍然驱动「该跑没跑」。只有当台账
  说「有调用」时才让位。若将来需要在有调用时也提示观测异常，那是另一个要素（例如健康面单独出 chip），
  不该挤进主徽标。
- **旧断言被改** → `views.test.jsx` 里那条 `serving + silent → 尚无调用` 是把缺陷写成了规格，改成
  `→ 在役` 并附注释说明。这是本改动里唯一需要「删掉一条守卫」的地方，理由必须留在注释里。
